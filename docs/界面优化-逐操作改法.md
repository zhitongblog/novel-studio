# 界面优化：逐操作改法（对标起点作家后台）

> 2026-09-21｜依据：起点作家专区写作页实拍 + `ui/index.html` 全量操作盘点
> 番茄作家后台本次没进去（登录态不在可用 profile 里），等开了再补一版对照。

## 0. 这次实际看了什么

- **起点**：`write.qq.com` 章节写作页（作品《重返1994》第45章草稿态）、作家专区首页、个人中心。
- **Novel Studio**：`ui/index.html` 922 行，提取出 **153 个按钮**，分布在 1 个主面板 + 约 20 个弹窗里。

先说结论：**主面板不是问题**。它已经做过分组——「此刻」看板 + 待拍板条 + 五个抽屉（接着写／查一查／这本书的样子／⚠️拿出去／这本书的设定），`danger-zone` 还单独做了警示文案。源码注释里能看到上一轮重构的取舍（380px 功能区 → 铺满工作区）。

**问题在弹窗层。** 153 个按钮里有 120 多个在弹窗里，每个弹窗各自发明了一套按钮排布、各自造词、各自处理"试一下"和"真的做"。

## 1. 起点后台值得照搬的五条

从那张写作页截图上能直接读出来的规律：

**① 整页只有一个主按钮。**
顶栏右侧是「保存」（描边）+「发布」（实心蓝）。其余全是线性图标（目录/大纲/素材）和一个 ⋮。工具条上的撤销、重做、查找替换、快速起名、作家的话、历史版本——**六个功能，零个实心按钮**。主次靠颜色和填充，不靠大小和 emoji。

**② 状态常驻，不用点就能看见。**
- 工具条右端：`✓ 保存于 17:53:32`
- 底部状态栏：`本章字数: 1170` ｜ `码字速率: 0 字/分`
- 左栏每个分组带计数：`草稿箱 (共1章)` `已发布 (共2卷，共44章)` `回收站 (共0章)`

作者任何时候都知道：存没存、写了多少、还剩什么。

**③ 三态收纳，删除可恢复。**
草稿箱 / 已发布 / 回收站。**删除不是消失，是移动。**

**④ 层级用面包屑选择器，不用跳页。**
`重返1994 / 第一卷 重生归来 ▾ / 公众章节 ▾` —— 换卷、换章节类型都在原地下拉，不离开编辑器。

**⑤ 高风险提示贴在动作旁边，不在动作之后。**
正文顶部一条红字："禁止发布违法违规内容，拒绝抄袭，拒绝AI直接参与网文创作"。它在**编辑区里**，不是发布时才弹。

## 2. 现状体检：六个具体毛病

都是从按钮清单里直接查出来的，不是推测。

### 毛病 1：同一件事，三个名字，两套入口

| 按钮 | 文字 | 位置 |
|---|---|---|
| `btnRewrite` | ♻️ 重写已写的章节 | 主面板「拿出去」 |
| `rdRewrite` | ♻️ 重写本章 | 阅读页 |
| `cwRedoBtn` | 🔄 重写这一章 | 共创弹窗 |
| `crGo` | ♻️ 开始重写 ▶ | 重写弹窗 A |
| `rwGo` | ♻️ 开始重写 ▶ | 重写弹窗 B |

`crGo` 和 `rwGo` **文字完全相同**，却是两个不同的弹窗。作者无从知道自己在哪个流程里。

**改法**：统一为一个词「重写」，一个弹窗，范围（本章／指定区间／整卷）作为弹窗内的参数。合并 `crGo`/`rwGo`。

### 毛病 2：用说明文字补交互缺陷

```
cvGrabChatGPT  📥 抓取封面（图已生成、只是没自动拿到时用）
cvGrabGemini   📥 抓取封面（图已生成、只是没自动拿到时用）
```

两个按钮文字一字不差。而括号里那句话等于承认："自动抓取有时候会失败，失败了你自己点这个。"

**改法**：抓取失败是状态，不是入口。生成中显示进度；失败了在**失败的那张卡片上**出现「重试抓取」，而不是常驻两个一模一样的按钮。

### 毛病 3：「试一下」和「真的做」并排摆

| 试跑 | 正式 | 同一弹窗 |
|---|---|---|
| `pbRpTest` 🧪 只改第1章试 | `pbRpGo` 🩹 覆盖这一段 ▶ | 发布 |
| `pbTest` 🧪 试发1章 | `pbGo` 📤 发布全部新章 ▶ | 发布 |
| `ifTest` 🧪 试导3章 | `ifGo` 📥 导入整本 ▶ | 导入 |
| `flReview` 📋 完本审稿（试评） | `flMark` ✅ 直接标记已完本 | 完本 |

有试跑意识是对的，但**试跑和正式同级并排**，只靠 🧪 区分。起点的对应关系是「保存（草稿）」和「发布」——不仅分主次，而且草稿是个**状态**，不是一次性动作。

**改法**：试跑结果要能停留。跑完 `pbTest` 应该进入"已试发 1 章，待确认"的状态，正式按钮此时才点亮。而不是试完什么也没留下、正式按钮一直亮着。

### 毛病 4：三个「停止」，各管各的

`btnStop`（写作）、`rbStop`（待拍板）、`pbStop`（发布）。三个长得不一样、位置不一样。长任务在跑的时候，作者要先找到是哪个在跑，才知道点哪个停。

**改法**：顶栏做一个常驻的**任务条**——当前在跑什么、跑到哪、一个停止。对标起点的「保存于 17:53:32」，占的是同一块位置。

### 毛病 5：删除没有回收站

`rdDelete 🗑️ 删除本章`、`rdDelReviewAll 🧹 清空全部自检`、`rdRenumber 🔢 全局重编号`、`rnSave 保存并全书生效 ▶`——四个不可逆或影响全书的操作，长得和普通按钮一样。

起点的删除是移进回收站（`回收站 (共0章)` 常驻可见）。

**改法**：章节删除改为移入 `.trash/`，阅读页左栏加「回收站(N)」分组。全局重编号和全书改名前做 git 存档（`btnRewrite` 的 title 里写了"动手前自动 git 存档"——这个机制已经有了，推广到另外三个）。

### 毛病 6：153 个按钮，几乎每个都带 emoji

emoji 在这里当图标用，但 emoji 没有粗细、没有统一光学重心、彩色抢眼。结果是**全部权重相同**，扫一眼找不到重点。起点写作页上一个 emoji 都没有。

**改法**：不必全删。定三档：
- **主操作**：实心底色 + 纯文字（发布 / 开始写 / 保存）
- **次操作**：描边 + 纯文字
- **工具**：线性图标 + 文字，emoji 只留在**分组标题**上（`✍️ 接着写`、`🔍 查一查` 这类抽屉 summary 保留，识别度高且只有 5 个）

## 3. 逐组操作的改法

### A. 主面板（`view-write`）— 小改

已经有分组，只做三件事：
1. 五个抽屉里目前有多个 `btn primary`（`btnCowrite`、`rbApply`、`rbContinue`）。**同屏只留一个主按钮**，按当前状态决定是哪个：没开写→「共创」；待拍板→「批准并继续」；写作中→任务条上的「停止」。
2. 顶栏 `writeTokens`/`writeStatus` 两个 badge 扩成**任务条**：在跑什么 · 第几章 · 已用 token · 停止。
3. `btnRename`/`btnReadFromWrite`/`btnOpenDir` 三个图标按钮保留，这是对的（起点同款做法）。

### B. 阅读页（`view-read`，`rd*` 12 个按钮）— 大改，对标起点写作页

这是和起点重合度最高的一页，直接照搬布局：

```
┌ 书名 / 卷 ▾ / 章 ▾ ──────────────  [保存]  [发布]  ⋮ ┐
│ ┌─左栏──────┐ ┌─────────────────────────────┐ │
│ │ 搜索章节   │ │ 撤销 重做 │ 查找替换 │ 自检 │ 历史  │ │
│ │ + 新建章节 │ │          ✓ 保存于 17:53:32   │ │
│ │ ▸草稿箱(1) │ ├─────────────────────────────┤ │
│ │ ▸已写(6)   │ │                             │ │
│ │ ▸回收站(0) │ │        正 文 编 辑 区        │ │
│ └───────────┘ └─────────────────────────────┘ │
│ 本章字数 3802 │ 目标 3000–3600 │ 上次自检 ✓通过      │
└──────────────────────────────────────────────┘
```

映射关系：
- `rdNavToggle 📑 目录` → 左栏常驻，不用切换
- `rdDelete 🗑️ 删除本章` → 移入回收站分组
- `rdEdit`/`rdSave`/`rdCancel` → 起点是**直接可编辑 + 自动保存**，没有"进入编辑模式"这一步。建议跟进：去掉 `rdEdit`，失焦自动保存，`rdSave` 降级为"立即保存"
- `rdDelReview`/`rdDelReviewAll` → 自检是章节的附属物，收进工具条的「自检」标签页，不占顶栏
- **底部状态栏是本项目的优势位**：起点只能显示字数和码字速率，Novel Studio 能显示 `本章字数 / 目标区间 / 上次自检结论`——这是规范里的硬指标，放这儿比藏在自检报告里有用得多

### C. 发布弹窗（`pb*` 11 个按钮）— 拆成两步

现在一个弹窗里塞了：书配置、保存配置、预览、创建作品、只改第1章试、覆盖这一段、读取番茄卷、试发1章、停止发布、发布全部新章。**十件事，四种时态混在一起。**

拆成：
1. **准备**（配置 + 读取远端卷 + 预览将发）→ 结果是一张"将发 N 章，卷映射如下"的清单
2. **执行**（试发 1 章 → 确认 → 发布全部）→ 带进度和停止

起点的对应物是"草稿箱 → 发布"两态。同理：**预览结果要能停留**，而不是看完就关。

### D. 其余弹窗（`nb*`/`cw*`/`rv*`/`ol*`/`cv*`/`vc*`/`rs*`/`st*`/`sd*`/`rn*`/`fl*`）— 统一模板

现在每个弹窗的按钮排布都不一样。定一个模板，全部套进去：

```
┌ 标题                                    ✕ ┐
│ 说明一行（这个操作会改什么、可不可逆）        │
│ ─────────────────────────────────────── │
│ 参数区                                    │
│ ─────────────────────────────────────── │
│ 结果区（跑完停留在这儿，不自动关）            │
│ ─────────────────────────────────────── │
│ [取消]                    [试一下] [执行 ▶] │
└─────────────────────────────────────────┘
```

规则：
- **取消永远在左下，主操作永远在右下**（现在有的弹窗取消在右、有的在左）
- 有试跑的，试跑固定在主操作左边一格
- **跑完不关窗**，结果留在结果区，主操作变成「再跑一次」或「应用 ▶」
- 弹窗标题用动词短语，和入口按钮**同词**（现在入口叫「重写已写的章节」，弹窗里叫「开始重写」）

### E. 完本（`fl*` 9 个按钮）— 改成检查清单

现在九个平级按钮：进入收尾冲刺、完本审稿（试评）、写完本感言、撤销收尾、直接标记已完本、完结就绪报告、完结收口、定位番茄申请完结入口、让作者按此补写结局。

这九件事**有先后顺序**，不是九个选项。

**改法**：做成一张带状态的清单（尾声写了没 / 完本感言写了没 / 全书完标注 / 设定已完结 / 番茄对账），每项自己带一个操作按钮，底部一个「申请完结」在全绿之前禁用。`btnFinale` 的 title 里其实已经写了"系统会逐项核对完本产物……缺了会退回来让它补"——**这个清单已经存在于后端，只是没画在界面上**。

## 4. 落地顺序

按"改动小 / 收益大"排：

| 序 | 做什么 | 影响面 | 收益 |
|---|---|---|---|
| 1 | 顶栏任务条（在跑什么·进度·一个停止） | 1 处 | 三个 Stop 归一，长任务可见 |
| 2 | 弹窗按钮模板统一（取消左 / 试跑中 / 主操作右，跑完不关窗） | 20 个弹窗，纯 CSS+少量 JS | 一致性，最大的一笔 |
| 3 | 合并 `crGo`/`rwGo` 两个重写弹窗，统一叫「重写」 | 2 处 | 去掉一个歧义入口 |
| 4 | 阅读页左栏常驻 + 回收站 + 底部状态栏 | 1 页 | 对标起点收益最高的一页 |
| 5 | emoji 三档降噪 | 全局 CSS | 视觉层级 |
| 6 | 发布弹窗拆准备/执行两步 | 1 个弹窗 | 最容易点错的地方 |
| 7 | 完本改检查清单 | 1 个弹窗 | 后端逻辑已有，只是没画出来 |

第 1、2 项做完，界面一致性就上了一个台阶，而且不动任何业务逻辑。
