# 需求：书库 Git 同步

> 状态：待排期（2026-09-29 提出）

## 为什么要有

**代码有 GitHub 兜着，书没有。**

2026-09-29 清点书库，实情是这样：

| 书 | 未提交文件 | 远端 |
|---|---|---|
| 重生赵云：这一世只做英雄 | 1160 | 无 |
| 鸿门拔剑：我项羽请沛公赴死 | 1063 | 无 |
| 我本凡人，奈何AI要修仙 | 114 | 无 |
| 国术神探：1900 | 100 | 无 |
| 岳飞：跟我讲规矩 / 岳飞：这一世 / 崇祯 / 圣女 / 国术 / 岳雷 | 6–20 | 无 |

**十本书没有一本配了远端**，几百万字全在一块盘上。
而且多数书连本地提交都不做——`scaffold.gitInit` 只在建书时 `git init`，
之后没有任何一条路会自动提交，所以工作区越攒越脏，
真要回滚也找不到干净的还原点。

触发这条需求的事故：2026-09-28 夜里给《我本凡人》续写了 84 章，
第二天早上发现**一个字都没进 git**。那晚 autopilot 被杀过两次，
只要中间任何一环把文件写坏，这 84 章就没了。

## 要做成什么样

### 一、自动存档（最低限度，先做这个）

写作链路上已经有天然的存档点，挂上去即可：

- **写完一批之后**（`afterbatch`，排版矫正/文风回正之后、节奏闸之前）
- **改稿之前**（`fixStyleRange` 现在靠我手工 `git commit` 存档，应该内置）
- **发布之前**（`publishToFanqie`，发出去的版本要能定位）

提交信息带上章号区间和触发原因，例如
`自动存档：续写 223–306（claude）` / `文风回正前存档 297–333`。

【关键】这类自动提交**只在书的仓库里做**，绝不碰 novel-studio 自己的仓库；
并且只 `git add` 书目录内的文件，不做 `git add -A .`（书目录外的东西不归它管）。

### 二、远端推送（要账号，得由作者点头）

- 书库配置里加 `remote`（每本书一个，或整个书库一个 monorepo）。
- 建议**私有仓库**：正文是未发表作品，公开等于提前泄底。
- 推送时机不必跟提交一样频繁——每天一次、或每次发布之后推一次就够。
- 推失败不许阻断写作，记一条 warn 就过（网络问题不该把写作卡住）。

### 三、界面与 CLI

- `novel sync --book X`（提交 + 推送）、`novel sync --all`
- 桌面版书架每本书显示「未提交 N 个 / 上次推送 X 天前」，
  跟断更告警放在一起——都是"这本书有没有在流血"这一类信息。

## 别做过头

- **不要自动 push 到公开仓库**，也不要默认开启推送：这是作者的账号和作品，
  外发是不可逆的，必须显式配置。
- **不要自动 merge / rebase / force push**。冲突就停下来报给人。
- **不要把 `.studio/` 里的运行时状态一并推走**（published-hashes、gates 判据、
  launch.ps1 这些跟机器走，不跟作品走）——该进 `.gitignore`。
- 大文件（cover.png、cover_bg.png）体积不大，可以进；
  但如果以后有音视频素材，要考虑 LFS 或干脆排除。

## 眼下的临时办法

在这个功能做出来之前，人工兜底：
`git -C "<书目录>" add -A && git -C "<书目录>" commit -m "存档"`
——至少每次大批量写作和改稿前后各来一次。
