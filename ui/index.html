🔍 复检

      
让 AI 复核并修正已写内容：逻辑/设定矛盾就地改、文风就地润色、故事合理性给方案、节奏/格局给前瞻提速方案。不改范围外章节、不新增后续章。

♻️ 重写

      
【推倒重写】不是润色。开始前会自动 git 存档，不满意可在书目录 git reset --hard 回退。写作中需先停止。

      
      
      
      

      

    

  


  
  

    

      
      
📤 发布到番茄

      
通过已登录的 Unzoo 浏览器驱动番茄作者后台。只发番茄还没有的新章（按全书章号去重，绝不重发）；重写过的旧章用「同步重写章」找番茄对应章覆盖。定时发布由番茄侧排程，建卷不可逆——默认不按卷、只追加发，零风险。

      

        
        
        
        
        
        
      

      
      
      
      

        
        
      

      

      

        
        
        
      

      

    

  


  
  

    

      
      
📥 从番茄导入图书到本地

      
通过已登录的 Unzoo 浏览器，把番茄上的整本书（卷结构 + 全部章节正文）拉到本地。导入后这本书就和本地书一样可用——完结收口、完本感言、发布对账都能在 app 里直接跑。常用于番茄独有、本地没有正文的书。

      

        
        
      

      
      

        
      

      

      

        
        
        
      

      

    

  


  
  

    

      
      
✏️ 改书名

      
改名会全书生效：更新设定圣经、章节索引、连贯性台账、各卷大纲、简介与三模型上下文里的《书名》。已写正文不变（正文里本就不含书名）。封面上的书名文字需重新生成封面才更新。写作中需先停止。

      
      

        
        
      

      

    

  


  
  

    

      
      
🏁 完本策略

      
收尾冲刺：autopilot 改发"收束令"，逼向大高潮+结局、对照台账逐条回收伏笔、给人物结局。作者收完输出「【完本待审】」后，主编核对完本清单（主线/伏笔/人物/卖点/有无烂尾），通过才标"已完本"并干净停止；不过则退回补写。

      

      

        
        
        
        
      

      
完结收口（内部完本 → 番茄平台完结）：把收尾新增章发齐到番茄、对账平台状态。番茄签约/征文书完结需编辑审批，软件不替你按下不可逆的提交。

      

        
        
        
      

      

      

      

        

        

      

    

  


  
  

    

      
      
📋 大纲审稿

      
换另一个模型当主编，按节奏/格局/爽点/逻辑/伏笔/规模审你的大纲，给出【硬伤/隐患/建议】分档意见，写入 reviews/大纲审稿-xxx.md。意见只供作者参考修订，不直接改大纲。

      
      
      

        
        
      

      

      

        

        

        

      

    

  


  
  

    

      
      
🎨 文风

      
选一个文风，或让 AI 据本书题材推荐。改完会重写本书写作规范，下次写作即生效（已写章节不变）。
